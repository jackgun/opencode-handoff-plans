# 任务卡与验收写法

按需要裁剪。重点是输入、产物和证据明确，不要求每份计划使用同样的标题或任务数量。

## 任务卡

```markdown
### T-ID：可观察到的结果

关联规则：R-ID（spec 中的决定及来源）
负责人/独占文件：具体范围
执行模式：契约式 / 精确执行；基线提交、指定工作区与分支、顺序及提交粒度。
输入依赖：生产模块、数据语义、契约版本；缺失时能做哪些独立工作
输出契约：函数/事件/记录及单位、空值、错误语义
生产接线：谁调用本产物，谁消费它；给出具体文件、符号和注册位置。

| 外部触发者 | 已注册入口 | 领域服务 | 事务记录/outbox | 已注册消费者 | 最终可观察结果 |
| --- | --- | --- | --- | --- | --- |
| 客户按钮、Webhook、页面或定时任务 | manifest handler/router/JobHandler | 函数或 service | 状态、审计、附件或通知行 | worker/callback/宿主适配器 | 对客回复、受控投递、持久化状态 |

身份与作用域：actor、tenant、会话、版本、附件 asset 的可信来源；禁止从请求 body/模型输出取得的字段。
接线基线：搜索入口、queue、helper 的实际引用；若只有测试调用或未注册 consumer，标为未接线并拆出补齐任务。

验收场景：
| 初始条件与输入 | 返回/状态/版本 | 写入与外部调用 | 验证层级 |
| 明确样例 | 明确结果 | 应发生及不应发生 | 单元/组合/实库/真机 |

先写可运行测试：给出 fixture 来源、实际入口调用与断言；每个写库/发送/状态变化路径至少有一个成功场景和一个零副作用反例。异步链路保留 producer、outbox 和 consumer；外部网络可替换为受控 sender，不能替换被验的生产接线。

竞争/超时/唯一投递（适用时）：列参与者、受控交错点、每次 CAS/claim 的 `true`/`false`/异常处理、唯一同步回复权和 outbox 的创建条件。既有 XFAIL 或复现转绿时，保留其 Event/Barrier、挂起点及原始时序；除实库双连接竞争外，至少有一条真实入口 → worker → outbox → 受控 sender 的组合测试，证明每个原始交错的最终结果。若无法建立 durable 所有权或消费者，返回可重试失败，不能返回“已排队”。`retryable_error` 还要写明重试上限、dead 终态和人工/扫描处置。
运行：工作目录 + 复用运行环境 + 精确命令。
预期红：缺少的行为及其失败方式；修复时优先展示行为断言失败。
实现材料：契约式给必要提示；精确执行给新文件全文及已有文件的唯一匹配查找/替换块，按步骤验证锚点。
偏差边界：零匹配/多匹配时停止受影响步骤；范围内必要修正记录证据和回归测试，触及设计、红线或验收门槛时请求决策。
预期绿：上述行为通过，必要回归通过。预期与实测分开记录，未演练不写成已通过。
环境缺口：准确排除项、原因、补跑负责人及命令；不能用局部通过替代未完成验收。
完成证据：规则对应的入口级测试、提交和注册点；未获得的外部证据单列为 blocked，不能用 mock 或“已入队”替代送达、客户接收或真机处理。
```

## 示例：持久化闭环

弱写法：“实现 CAS、序列化和去重，测试通过。”

可验收写法：

- 首次事件直接产生 version=2 时，数据库列和 JSON 均为 2。
- 使用含 Decimal/date/房源对象的状态，调用真实 store 保存；销毁本次内存状态，再从 store 读出；下一次合法事件正常推进。
- 重复 message_id 返回原回执，状态不二次推进；旧版本和不同 actor/channel/platform/tenant 不修改目标记录。
- 连接工厂每次返回不同 context 对象，断言被 enter 与 exit 的是同一个对象；锁失败和业务异常均释放资源。
- 以上 handler 组合测试保留真实 store 和编解码；外部上游可用确定性 fixture。
- 真正的事务竞争另用隔离 PostgreSQL 的两个连接测试；未运行时不能据内存结果宣称锁竞争已验收。

## 示例：超时回复的唯一所有权

弱写法：“新增 CAS、outbox 和双连接测试；同步与异步只有一个会赢。”

可验收写法：

| 受控时序 | 可作出同步回复的参与者 | 持久化结果 | 必须证明 |
| --- | --- | --- | --- |
| 外层入口超时早于调用创建 | 无 | 预留记录转 deferred；后续绑定、完成后恰一条 outbox | 入口先返回 queued 前已完成转交，worker 后续经受控 sender 投递一次 |
| worker 在最后一次查询后完成 | 无 | 超时转交与结果登记构成一条 outbox | 保留原屏障；不能把它改成单次 `request_deferred()` 断言 |
| 内层完成先于外层返回 | 最外层交付边界 | `sync_returned`，outbox 为零 | 外层实际交付正文；若外层已超时则不得让内层提前占用同步所有权 |
| CAS 返回 false 或存储异常 | 由既有 durable owner 决定；未知时无 | 不作虚假 queued 承诺 | 返回可重试失败，或证明既有 owner/outbox 已可被注册 consumer 消费 |

写入调用结果和创建 outbox 需要同一事务时，测试登记失败、未找到所有权及提交失败：不得把技能标为已完成后仅记录日志。对 `retryable_error` 覆盖退避、达到上限进入 `dead`、固定幂等键和人工处置入口；Hub 接受不是客户已收到。

## 示例：输入语义表

先确定产品支持的表达，不把下表当成各项目必须原样支持的语法。

| 输入类别 | 样例 | 期望 |
| --- | --- | --- |
| 上限 | 预算2000.50以内 | max=2000.50，保留金额精度 |
| 下限 | 至少1999.99 | min=1999.99 |
| 范围 | 1500.5–2000 | 支持此分隔符则完整解析，否则请求澄清；不能取成5–2000 |
| 歧义 | 2000元或3000元 | 不推进，要求确认 |
| 费用咨询 | 2000元包含哪些费用 | 保留步骤，进入规定的问答/澄清路径 |
| 中文金额 | 两千五、两千零五 | 按已定义规则解析或澄清，不局部截取 |
| 非法 | 负数、NaN、倒置范围 | 明确拒绝 |
| 菜单边界 | 每档端点与相邻最小货币单位 | 标签、编码、解析、筛选一致 |

对金额精度明确选择：只支持到分、允许更多精度或拒绝超精度；不要一边使用0.01分档，一边不限制输入精度。

## 示例：状态转换与副作用

| 当前状态/输入 | 下一步 | 版本/记录 | 外部行为 |
| --- | --- | --- | --- |
| 活跃/合法回答 | 下一问题 | 按契约推进一次 | 仅必要的实时读取 |
| 活跃/重复消息 | 原回执 | 不推进 | 不重复调用 |
| 活跃/取消 | cancelled | 保存终态 | 不查询库存 |
| 终态/普通咨询 | 保持终态 | 不新建采集 | 规定的咨询回复 |
| 终态/显式重开 | 新意向 | 新ID，旧记录保留 | 提供用户实际可触达的重开入口 |
| 任意/旧版本选择 | 失效回复 | 不修改、不新建 | 不发起业务副作用 |

这只是示例；是否重新发菜单及是否增加版本必须在项目中统一决定。

## 示例：菜单协议与配置生命周期

如果一个状态机同时支持菜单选择和自由输入，测试不能只构造领域函数期待的理想参数。先把宿主实际注入的形状列为契约：

| 客户操作 | Core/宿主交给 handler 的值 | 必须断言 |
| --- | --- | --- |
| 回复序号、完整 label 或菜单 token | 已声明 option 的 selection；文本可能是旧问题或为空 | 写入该 option 的规范值，且会话只消费一次 |
| 不点“其他”直接输入自由文本 | `text_selection` 的 selection 加客户 text | 保存完整客户 text，不能把空 selection value 写入字段 |
| 先选“其他”再输入 | 首轮重发输入提示；次轮是 text path | 两轮都不提前推进，第二轮保存完整文本 |
| 空白或超长自由文本 | 与产品约定一致 | 不推进、不覆盖已有字段、不产生后续副作用 |

需要配置目标的通知还应覆盖状态变化，而不只覆盖创建规则：

| 初始条件 | 事件 | 对新 outbox | 对既有 pending outbox | 受控 sender |
| --- | --- | --- | --- | --- |
| 已配置且启用 | 产生业务事件 | 按规则入队 | 正常处理 | 可发送 |
| 已配置后禁用 | 产生业务事件 | 不入队 | 按产品规则保留或取消，不能发送 | 不调用 |
| 禁用后重新启用 | 下一次 drain/业务事件 | 按明确规则恢复 | 按明确规则恢复或仍保持取消 | 与规则一致 |
| 删除目标 | 下一次 drain/业务事件 | 不入队 | 按明确清理策略处理 | 不调用 |

以上表格只适用于启用状态实际控制投递的系统；若产品选择“禁用只隐藏 UI”，必须把该不同语义写进规格和页面文案。

## 示例：上游未知与实际接线

分别记录原始字段、normalizer 后字段、单位/语义证据、对客投影。若 normalizer 将缺失状态转为0，而0又表示空房，测试必须把原始缺失值送进实际适配链路，确认不会变成确定空房。

对临期规则分别验收：日期公式正确；当前租约证据完整时实际入口按阈值变化；证据缺失时安全降级。第三项不能代替第二项。
